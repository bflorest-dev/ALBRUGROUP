# Ajustes Community: SideBar, Proveedores, Campañas y Zonas

  ## Summary

  Se ajustará COMMUNITY manteniendo PrimeNG y sin tocar backend. La vista quedará dividida en dos accesos del
  SideBar: Mantenimiento y Metricas. Dentro de Mantenimiento vivirán los tabs CRUD actuales; Metricas será una ruta
  separada con estado informativo hasta que exista endpoint de efectividad.

  ## Key Changes

  - SideBar y rutas:
      - Agregar rutas /app/community/mantenimiento y /app/community/metricas.
      - Cambiar el menú de COMMUNITY en /(frontend)/PrivateLayoutComponent para mostrar Mantenimiento y Metricas.
      - Redirigir /app/community hacia /app/community/mantenimiento.
      - Quitar Metricas de los tabs internos de mantenimiento.
  - Ajustes visuales:
      - Separar mejor span y strong en las cards de métricas rápidas para que el número no quede pegado al texto.
      - Mantener estilo PrimeNG y tema visual COMMUNITY.
      - UI propuesta: chips con días seleccionados + botón + que abre/activa un p-select con opciones 1..31.
      - No permitir duplicados; permitir quitar días seleccionados.
      - Enviar al backend el array numérico cortesFacturacion.
  - Campañas:
      - En la tabla, columna WhatsApp, agregar botón lápiz.
      - El lápiz abre un p-dialog compacto con el número actual y botones Guardar/Cancelar.
      - Guardar usará el endpoint existente PUT /leads/campanas/{idCampana}.
  - Zonas:
      - Cambiar el tab a una bandeja funcional: tabla de zonas + botón Agregar Zona.
      - Cada fila tendrá botón Editar.
      - Agregar y Editar usarán el mismo p-dialog.
      - Al editar, copiar reglas existentes al formulario y permitir quitar/agregar reglas antes de guardar.
      - La edición seguirá usando el comportamiento actual del backend: reemplazar todas las reglas con el payload
        final.
      - Builder de reglas:
          - Campo Nivel: DEPARTAMENTO, PROVINCIA, DISTRITO.
          - Navegación jerárquica usando endpoints existentes de ubigeo.
          - Botones de criterio: INCLUIR verde y EXCLUIR rojo.
          - Botón para agregar la regla a una lista visible.
      - Para mostrar nombres en reglas existentes, el frontend cargará/cacheará el directorio ubigeo al abrir
        edición por primera vez.

  ## API / Interfaces

  - No se cambia backend.
  - Se agregan métodos frontend en /(frontend)/CommunityLeadService para:
      - listar departamentos
  - Se ajustan tipos frontend de ZonaResponse/reglas si hace falta para reflejar nivelGeografico, geoId, criterio.
  - CommunitySection quedará solo para tabs de mantenimiento: proveedores, cuentas, campañas, zonas, planes,
    promociones.

  ## Test Plan

  - Ejecutar npm run build.
  - Validar SideBar:
      - Mantenimiento abre /app/community/mantenimiento.
      - Metricas abre /app/community/metricas.
      - /app/community redirige a mantenimiento.
  - Validar Proveedores:
      - Agregar/quitar cortes del 1 al 31.
      - Registrar proveedor envía array numérico.
  - Validar Campañas:
      - Textos visibles usan Campaña.
      - Editar WhatsApp desde lápiz actualiza y refresca tabla.
      - Editar zona precarga reglas existentes con nombres resueltos.
      - Quitar/agregar reglas y guardar reemplaza correctamente.
  - Validar que no se rompen Planes y Promociones.

  - Resolver nombres de reglas existentes puede cargar bastante ubigeo la primera vez, pero queda cacheado en
    memoria durante la sesión.
  - La edición de WhatsApp será con modal compacto, no inline, para evitar cambios accidentales.
